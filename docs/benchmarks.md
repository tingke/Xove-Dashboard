# 性能基准报告

> 基准测的是**插件热路径的纯逻辑层**——随库规模扩展的支配成本（扫描/解析/建模/排序/虚拟窗口/行级写回）；DOM 渲染与 Obsidian 内部索引不在 Node 基准范围内（口径见下）。

## 环境

| 项 | 值 |
| --- | --- |
| 日期 | 2026-10-19 |
| 机型 | Apple M5（10 核）· macOS |
| Node | v24.20.0 |
| 插件版本 | 0.5.0 |
| 生成器 | `scripts/bench-vault.ts`（固定种子 20261019，可复现） |
| 方法 | 每场景预热 2 次、取 3 次中位数 |

## 四档 × 五场景（中位数，ms）

| 场景 | 1k | 5k | 10k | 50k |
| --- | ---: | ---: | ---: | ---: |
| S1 扫描+解析+建模（≈启动主导成本） | 14.3 | 67.1 | 135.0 | 1787.4 |
| S2 首屏数据准备（今日集合+排序+虚拟窗口+时间块） | 0.3 | 1.4 | 2.1 | 11.3 |
| S3 视图切换 ×3（过滤+排序+窗口） | 0.3 | 0.9 | 1.6 | 13.1 |
| S4 单次写回（行级变更+重复推进） | 0.004 | 0.010 | 0.001 | 0.001 |
| S5 批量完成 100 条（100 写回+全量重扫） | 16.7 | 73.7 | 152.9 | 1980.5 |

合成库构成：任务（一任务一文件，85% 待办 / 10% 已完成 / 5% 已取消，12% 重复，8% 多日）+ 项目（task/250 个）+ 普通笔记（task/10）+ 灵感看板单文件（task/50 条）。10k 档 ≈ 40 项目 / 11081 文件 / 5.7 MiB。

## 预算（10k 档门禁）

`scripts/bench-budgets.json`：**S1 ≤ 400ms · S2 ≤ 12ms · S3 ≤ 10ms · S4 ≤ 0.05ms/op · S5 ≤ 500ms**（首轮实测 ×约 2 倍余量）。

超预算时按 [release-checklist.md](./release-checklist.md) 记录豁免或先优化；换参考机型需重新基线化。

## 口径与局限（如实声明）

1. **YAML 解析**：Obsidian `parseYaml` 不可在 Node 调用，基准使用受控子集解析器（平铺标量 / 行内数组 / 一层嵌套块，`scripts/bench.ts` 内实现），只保证解析本生成器产出的格式；真实用户若使用复杂 YAML（块标量、锚点），S1 成本会高于本口径。
2. **文件 IO**：以 `fs.readFile` 镜像 `vault.cachedRead` 的并发形态；Obsidian 缓存层的差异不在范围内。
3. **S5**：磁盘写入未计入（`vault.modify` 的 syscall 相对解析成本可忽略），已分项报告「行级变更 100 次」与「全量重扫 1 次」。
4. **DOM/渲染**：真实渲染帧耗时无法在 Node 测量，S2/S3 只覆盖渲染前的数据准备（这也是随规模扩展的部分）。

## 复跑

```bash
npm run bench                 # 四档全跑
npm run bench -- --scale=10k  # 单档
npm run bench:check           # 10k 门禁（对照 bench-budgets.json）
```
